# Super-soft Korean → Ukrainian engine mode: 100% input coverage contract

**Date:** 2026-10-30  
**Status:** APPROVED REQUIREMENT / IMPLEMENTATION TODO  
**Runtime constraint:** deterministic, browser-local; no neural model and no runtime API.

## 1. Product requirement

Add a distinct **Super-soft / maximum-coverage** mode to the Kozak Kim Korean engine. Its hard acceptance target is **100% input coverage**, comparable in coverage intent to other G2P engines:

- Every modern Hangul syllable block in the input must receive a non-empty Ukrainian practical-reading candidate.
- No Korean syllable may disappear from the result because morphology, lexical identity, compound boundaries, or an IPA target mapping is unknown.
- Every source span must remain accounted for in the trace/provenance output.
- Whitespace, punctuation, digits, Latin text, Hanja, emoji, and other non-Korean literals must be preserved in their original positions unless an already documented, explicit normalization applies.
- Standalone compatibility Jamo and non-modern/archaic Hangul must receive an explicit typed fallback or preserved-source representation with a status; they must not silently vanish.

**100% coverage is not 100% pronunciation accuracy.** Report these separately:
1. input_coverage: proportion of Korean source grapheme clusters represented by a non-empty target candidate;
2. trace_coverage: proportion of source spans accounted for by a trace item;
3. verified_pronunciation_rate: independently evidenced share of output, if such evidence exists;
4. heuristic_share: proportion generated by low-confidence fallback.

Never present coverage as accuracy.

## 2. Mode relationship

Keep all existing modes and defaults unchanged:

- **Strict:** exact/source-backed and currently accepted rules only; fail-closed behavior remains intact.
- **Soft:** current closed-inventory morphological hypotheses; low-confidence and opt-in.
- **Practical:** current best-effort behavior; do not silently redefine it.
- **Super-soft:** new opt-in maximum-coverage mode. It may use progressively weaker deterministic fallbacks, but every fallback must be typed and visibly marked low-confidence.

Super-soft must not upgrade heuristic readings to NIKL-confirmed, lexical-exact, or normative status. It must not write fallback guesses into the exact lexical registry.

## 3. Required deterministic fallback ladder

Resolve each Hangul span in this order, without losing the original source:

1. Exact lexical / source-backed pronunciation.
2. Existing deterministic phonological rules and exact licenses.
3. Existing soft morphological hypotheses.
4. Existing practical same-eojeol phonological heuristic.
5. **Orthographic/phonemic fallback:** if a morphology-conditioned surface process remains ambiguous, produce a complete conservative reading from the decomposed Hangul sequence using the engine's declared underlying/representative segment model. Do not invent a liaison, saisiot insertion, compound split, or §15 interpretation. Mark the fallback as super-soft-orthographic-fallback / low confidence and retain the unresolved alternatives in the trace.
6. **Target-adapter completion:** every IPA token emitted by any preceding tier must have a deterministic Ukrainian rendering in a versioned, inspectable IPA→Ukrainian adapter. If the existing target inventory does not cover a token, add an explicitly reviewed fallback correspondence or a typed approximation rule at the IPA adapter boundary. Do not bypass IPA with direct Hangul→Ukrainian substitutions.
7. If a source character is not a modern Hangul syllable/Jamo and has no pronunciation contract, preserve it literally and record literal-preserved; this counts as source-span accounting but not as Korean pronunciation coverage.

No neural model, remote service, browser network call, or nondeterministic lookup is allowed at runtime.

## 4. Mandatory invariants

- IPA (or an explicitly typed phonetic fallback result) remains the sole input to Ukrainian target adaptation.
- Preserve syllable boundaries, source offsets, rule provenance, tone/length/other features already represented by the engine, and unresolved alternatives.
- Never silently resolve §15 substantive liaison, §29 ㄴ-insertion, §30 saisiot, R016, or compound morphology merely to fill output. Use the orthographic fallback tier if no evidence-supported resolution exists.
- Strict, Soft, and Practical output must remain byte-for-byte unchanged for existing fixtures unless a separate approved change explicitly targets them.
- The UI must label Super-soft as maximum coverage / low confidence, explain that some readings are fallback approximations, and keep it opt-in.
- Result objects must expose coverage counts and per-span statuses; a single aggregate status must not conceal mixed confidence.

## 5. Acceptance tests

### Exhaustive unit coverage
- Exercise all 11,172 modern Hangul syllables individually in Super-soft mode.
- Assert each receives non-empty IPA, non-empty Ukrainian candidate, and exactly traceable source coverage.
- Exercise all valid onset × vowel × coda combinations and round-trip source offsets.
- Test decomposed Jamo, compatibility Jamo, archaic Jamo, isolated Jamo, and malformed/mixed Unicode input with explicit status behavior.

### Adversarial integration coverage
- Unknown native Korean words, unknown Sino-Korean words, proper names, neologisms, slang, inflections, particles, compounds, ambiguous morphology, §15-sensitive forms, §29/§30 cases, and long mixed-script passages.
- Assert that no Hangul span is dropped and every target candidate is non-empty.
- Assert whitespace, punctuation, digits, Latin, Hanja, emoji, and line breaks are preserved.
- Assert the fallback never claims exact/NIKL evidence and never mutates the exact lexical data.

### IPA/target adapter coverage
- Derive the complete IPA token inventory reachable from all 11,172 syllables plus contextual variants.
- Assert every reachable token/sequence has a target-adapter outcome and no unknown IPA fragment remains in Super-soft mode.
- Test that all target fallbacks are explicit, versioned, traced, and low-confidence where appropriate.

### Cross-runtime and regression
- Shared fixtures must produce deterministic parity in Python and browser implementations where both runtimes expose the same mode.
- Run all existing Strict/Soft/Practical regressions unchanged.
- Run npm test, npm run build, Python tests, data/schema/generator checks, exact-head CI, and deployed browser smoke before calling the feature DONE_VERIFIED.

## 6. Initial repository findings (2026-10-30)

- The browser pipeline already has strict, soft, and practical morphology modes in engine_convert.js / engine_rules_ctx.js.
- The current Soft layer is intentionally narrow: it unlocks only selected R002/R003/R007 formal-ending cases and explicitly refuses several ambiguous cases.
- Practical mode already attempts to fill some same-eojeol morphology gaps, but it intentionally leaves saisiot and other lexical-only cases unresolved.
- The conversion loop can still emit empty target output for unresolved morphology, unsupported standalone Jamo, or an IPA sequence without an IPA→Ukrainian mapping. Therefore the existing Practical mode is not evidence of 100% coverage.
- Existing test engine-shared-hangul-properties.test.mjs exhaustively decomposes all 11,172 modern Hangul syllables, but this does not establish end-to-end IPA or Ukrainian target coverage.
- Existing test soft-heuristic-morphology-formal-endings.test.mjs validates the narrow Soft layer and negative controls; it is not a maximum-coverage test.

## 8. Non-goals and release wording

Do not claim “100% correct”, “complete Korean pronunciation”, or “NIKL-complete”. The supported claim after passing coverage acceptance is:

> “Super-soft mode returns a deterministic Ukrainian reading candidate for 100% of modern Hangul syllable input covered by the exhaustive test, using explicit low-confidence fallbacks where lexical or morphological evidence is unavailable.”

This claim must be narrowed if exhaustive tests expose unsupported Unicode or runtime boundaries.
