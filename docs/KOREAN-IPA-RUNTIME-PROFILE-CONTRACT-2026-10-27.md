# Korean IPA runtime-profile contract — 2026-10-27

## Decision status

**Status: PARTIAL / acceptance blocked.** This document defines the acceptance boundary; it does not claim that the current Python and browser IPA strings are equivalent, and it does not choose a winner by implementation convenience.

The required processing order remains:

`Korean orthography → structural/morphophonological analysis → Korean surface form → explicitly typed IPA profile → reviewed IPA-to-Ukrainian adapter → Ukrainian practical orthography`.

Ukrainian adaptation is out of scope until the Korean surface and IPA layers pass their own acceptance gates.

## Current observable contracts

| Runtime | Available representation | Current sibilant behavior relevant to the mismatch | Status |
|---|---|---|---|
| Python `src/korean_ukrainian/ipa.py` | `ipa_profile`, integer `ipa_profile_version`, `ipa_profile_level`, and `ipa_profile_status` are emitted for `phonemic`, `broad`, and `narrow` | Broad fortis ㅆ is `s͈`; the opt-in narrow profile is explicitly partial and currently models lenis ㅅ contexts, not a general fortis-palatalization rule | Metadata implemented; IPA segment/feature sequence and shared adapter gate remain absent |
| Browser `src/app/engine_convert.js` | Public result includes `ipa_profile`, integer `ipa_profile_version`, `ipa_profile_level`, and `ipa_profile_status`; profile IDs are versioned strings (`browser-legacy-contextual-v1`, `browser-surface-mode-legacy-v1`) | Contextual branch renders fortis ㅆ as `ɕ͈` before members of `J_VOWELS`, including ㅣ | Common metadata field names now exist in both runtimes; profile IDs and levels intentionally differ, and cross-runtime equivalence remains unverified |

The difference is a real **contract mismatch**, but not yet a proven phonetic error. A string generated by one profile must not be compared as though it came from another. Do not silently replace `ɕ͈` with `s͈`, or the reverse, and do not let a parallel IPA audit obscure the actual IPA passed to the target adapter. Both runtimes now emit the shared profile metadata keys on their normal and lexical/phrase return paths; the lexical early-return omission was fixed and regression-tested on code/test head 8d19b204a655c998ee9d3ca1cfd70afbfa7c7f7. The remaining gaps are a shared structured segment/feature/boundary object, independent profile adjudication, and exclusive production wiring through the fail-closed adapter gate.

## Required acceptance contract

1. **Name the profile at the boundary.** Every IPA result used for parity or downstream adaptation must carry a profile identifier and version, not just an untyped string.
2. **Separate segmental representation from serialization.** Segment sequences, syllable boundaries, word boundaries, length, aspiration, fortisness, tie bars, and other diacritics must be represented or preserved explicitly. Serialization-only changes may not change the underlying sequence.
3. **Do not conflate profiles.** Phonemic, broad surface, and narrow phonetic outputs are separate values. A narrow profile marked partial cannot be used as accepted target input.
4. **Use paired source-form fixtures.** For each reviewed form, retain the Korean source, licensed surface-Hangul result, runtime, profile/version, raw IPA, expected feature/boundary sequence, evidence URL or source-register ID, adjudication status, and target-adapter eligibility.
5. **Make uncertainty executable.** Unreviewed cases must be labelled `UNADJUDICATED` or `UNMAPPED`; they must not be silently coerced into the nearest known symbol.
6. **Keep the Ukrainian adapter downstream.** IPA acceptance tests must test IPA outputs directly. Target orthography must not be used to decide which Korean IPA representation is correct.

## Immediate regression scope

The first paired fixture set must cover ㅅ and ㅆ before:
- ㅣ and the explicitly listed `J_VOWELS`;
- vowels outside that contextual set, including ㅗ/ㅛ and ㅠ;
- word-internal and word-initial positions;
- matched forms whose surface-Hangul output is already licensed.

The source studies already cited in `src/korean_ukrainian/ipa.py` support a *partial* narrow profile for lenis /s/; they do not by themselves settle the fortis /s͈/ profile or establish that the browser's current output is equivalent to Python broad IPA. Kang (2010) reports measurable coarticulatory spectral differences for /s/ before /i, ye, ya/ and a distinct pattern before /yu, yo/; this supports treating vowel contexts separately, but does not justify automatically rewriting tense /s͈/ as [ɕ͈]. A 2020 Seoul Korean study reports both lax and tense sibilants and notes palatalized variants before /i/ alongside speaker-related variation. These abstracts establish phonetic variability, not a single categorical IPA rendering for every speaker. Sources: https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART001444770 (Kang, 2010, pp. 3–18; accessed 2026-10-27); https://kci.go.kr/kciportal/landing/article.kci?arti_id=ART002585434 (Kong & Kang, 2020, pp. 1–19; accessed 2026-10-27). New mappings require direct source review, not analogy from the lenis series.

## Additional aspiration evidence and unresolved profile conflict — 2026-10-27

Holliday and Reidy's LabPhon 15 production poster (2016; https://jjholliday.github.io/files/Holliday%20%26%20Reidy%202016.pdf) reports a small study of six female native Korean speakers producing 18 word-initial CV tokens for /sʰ,s*/ before /a,i,u/. It describes aspiration for lenis /s/ as context-dependent, reduced or absent before high vowels, and palatalization before /i/; palatalization of fortis /s*/ is variable. This is a conference poster with a limited speaker sample, not a normative or universal transcription standard.

This evidence raises a concrete review question for the current research-only narrow profile: onset_ipa currently emits [sʰ] for lenis ㅅ in every vowel context except the configured ㅣ/ㅖ/ㅑ set, where it emits [ɕʰ]. The poster's high-vowel findings caution against treating aspiration as uniform before /u/ and /ɨ/, while its discussion of reduced aspiration before /i/ does not independently settle whether [ɕʰ] or [ɕ] is the best categorical output. Kang (2010) supports context-sensitive palatalized acoustic quality before /i, ye, ya/ but does not by itself adjudicate aspiration. These sources therefore expose an evidence gap; they do not authorize an automatic replacement rule.

**Decision:** leave the narrow profile marked partial/research-only, do not change the broad default or Ukrainian target mapping, and keep the target-adapter allowlist empty. Acceptance requires a paired ㅅ/ㅆ fixture matrix for /a, i, u, ɨ, ye, ya, yo, yu/, word-initial and word-internal positions, explicit treatment of speaker/context uncertainty, and independent adjudication before any profile can become target-compatible. The poster's license/redistribution terms have not been assessed; the source is registered for research traceability only.

## Implementation update — 2026-10-27

The browser result and Python IPA result now both emit the common metadata keys `ipa_profile`, `ipa_profile_version`, `ipa_profile_level`, and `ipa_profile_status`. The Python profile IDs distinguish phonemic, broad, and partial-narrow outputs; browser profile IDs distinguish legacy contextual and surface-mode outputs. A shared fixture at `tests/fixtures/korean-ipa-profile-pairs-2026-10-27.json` preserves the known `ㅅ`/`ㅆ` examples separately per runtime and explicitly labels them `UNADJUDICATED` with target-adapter eligibility `UNVERIFIED`. This is a versioned metadata boundary, not yet a full typed IPA representation: segments/features/boundaries are not yet a shared structured object. The fail-closed adapter gate is implemented and tested, but it is not yet the exclusive production entry point and no profile is allowlisted. The lexical/phrase early-return path was found to omit version/level metadata; that path now emits all four metadata fields and has a regression assertion.

The seed-portfolio CI failure on `4379463aab4f5a829c61ed666deb28cafffa1a6e` was unrelated to pronunciation: the triage script hard-coded 994 Strict pairs although the engine can legitimately leave a variable number of cases unresolved. The fix now accepts a variable pair count only when pair IDs are a subset of the 1,000 pinned dev prediction IDs and the same pair-ID set is produced for all three seeds. A mismatch between seed pair sets still fails closed. Exact-head verification is pending for the fix.

## Fail-closed target adapter guard — 2026-10-27

The function ipaTargetForProfile(source, ipaResult, options) is now available in src/app/engine_ipa.js. It accepts a complete IPA result object rather than a bare IPA string and requires explicit profile ID, positive integer version, level, status, and IPA payload. It rejects missing metadata, unadjudicated profiles, partial research-only profiles, and any profile not present in ADAPTER_COMPATIBLE_IPA_PROFILES.

The allowlist is intentionally empty. A successful string-to-target mapping is not evidence that the pronunciation profile is linguistically valid or that its features are safely representable in Ukrainian. A profile may be added only after independent phonetic adjudication, a stable versioned contract, cross-runtime acceptance, and target-inventory review. The legacy raw-string APIs remain available for existing runtime paths and diagnostic compatibility; therefore this guard is a new fail-closed API, not yet a claim that all production calls are forced through it.

Tests in tests/ipa-ukrainian-trace.test.mjs cover missing metadata, unadjudicated broad IPA, partial narrow IPA, unregistered purportedly approved profiles, and complete profile metadata on a lexical phrase return. The exact code/test head 8d19b204a655c998ee9d3ca1cfd70afbfa7c7f7 passed tests, system verification, and browser integration; remaining research diagnostics are tracked separately.


## Shared cross-runtime fail-closed fixtures — 2026-10-27

`tests/fixtures/ipa-profile-gate-cases.json` is the shared negative contract suite consumed by both `tests/ipa-ukrainian-trace.test.mjs` and `tests/test_ipa_target_renderer.py`. It covers a legacy raw string, missing metadata, empty IPA, zero and boolean versions, unadjudicated status, partial research-only status, and an unknown profile claiming compatibility. The expected outcomes are adapter rejection reasons, not IPA gold labels. Python explicitly excludes booleans from integer profile versions, matching JavaScript's `Number.isInteger` behavior. The adapter-compatible profile sets remain empty; these fixtures cannot be interpreted as acceptance of any profile.

The new shared fixture and both runtime test consumers are committed, but remain `PARTIAL` until exact-head CI completes. They do not remove legacy raw-string APIs or establish exclusive production routing through the typed boundary.
