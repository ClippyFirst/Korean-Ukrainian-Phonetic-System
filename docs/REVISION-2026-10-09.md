# Korean–Ukrainian system revision — 2026-10-09

## Scope

This pass reviewed the browser runtime, the Python phonology/IPA layer, adversarial regression tests, and the validation corpus. It did not attempt to infer a complete Korean lexicon or claim native-speaker adjudication for every lexical item.

## Bugs found and fixed

1. **Artificial spacing in IPA and Hangul analysis.** Literal spaces were themselves joined with separators, producing runs such as triple spaces. The renderer now preserves input whitespace and punctuation and inserts separators only between adjacent Hangul units.
2. **The “Structure Hangul” panel showed mutated surface jamo.** Liaison and fortition modified the same objects used for decomposition, so e.g. 음 could be displayed as ㄹ+ㅡ+ㅁ rather than its written onset ㅇ. The engine now snapshots orthographic units before applying pronunciation rules; unresolved ㅢ also retains its decomposition.
3. **Missing final representative for ㅍ in the browser engine.** This prevented the coda from participating in nasal assimilation and representative-based fortition. ㅍ now maps to its final representative ㅂ before those contextual rules.
4. **Complex-coda splitting in Python IPA.** `split_coda` previously returned Unicode code points, leaving a composite compatibility jamo such as ㄳ unsplit. It now returns its phonological components, so phonemic IPA/segment analysis can represent the underlying components before surface neutralization.
5. **Broad IPA under-reported voicing after sonorants.** The Python IPA layer only voiced selected lenis stops after an open syllable and omitted ㅈ. It now reflects broad surface voicing for ㄱ/ㄷ/ㅂ/ㅈ after an open syllable or a nasal/liquid coda; the phonemic level remains distinct.
6. **Complex ㅎ-coda aspiration in the Python rule layer.** R004 did not aspirate a following lenis consonant after ㄶ/ㅀ while retaining ㄴ/ㄹ. The rule now covers examples such as 많다 [만타] and 싫다 [실타].
7. **A regression test itself was wrong.** The expected broad IPA for 앉아 was updated to [an.dʑa] for the liaison onset, and a malformed test loop / syntax introduced during the audit was corrected.

## Added or strengthened regression coverage

- Intervocalic/sonorant-conditioned voicing, including 표준.
- Nasalization of ㅍ before a nasal (앞문).
- Aspiration after ㄶ/ㅀ (많다, 싫다).
- Complex-coda component splitting at the phonemic level.
- Preservation of written Hangul decomposition under liaison.
- Whitespace and punctuation preservation in IPA/analysis.
- Explicit structure output for unresolved ㅢ.
- Validation-corpus cases V023–V026.

## Scope and limitations that remain

- The Ukrainian output is an author-designed practical phonetic-graphemic system, not an officially standardised Ukrainian transcription standard.
- The browser engine is not a full lexicon/morphology-aware Korean pronunciation engine. Exceptions such as 값없다 [가법따], 의견란 [의견난], and context-sensitive ㄼ/ㄴ-insertion cases need explicit lexical or morphological licensing rather than broad string heuristics.
- Cross-word assimilation is intentionally not inferred across literal spaces/punctuation in the browser layer; phrase-level connected-speech mode needs an explicit user/model boundary policy.
- ㅢ remains unresolved in the browser because its realization depends on lexical/morphological position and allowed variants. This is preferable to silently outputting a falsely universal vowel.
- Broad IPA is rule-supported, not narrow acoustic IPA. The current inventory is not a pronunciation dictionary and does not prove every word's lexical reading.
- Korean standard pronunciation rules and a selected test corpus cannot establish that all Korean names, loanwords, dialect forms, or lexical exceptions are covered.

## Verification

GitHub Actions is the release gate for Python tests across supported Python versions and the web tests/build. The revision is complete only when the latest commit's workflow runs are green; a successful earlier commit is not evidence that later changes pass.
