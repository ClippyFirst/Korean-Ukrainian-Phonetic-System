# Source-backed Korean runtime improvements — 2026-10-24

## Scope and status

**Implementation committed; partial verification completed, full exact-head verification pending.** This change makes two narrow, source-attested improvements to the practical g2pK browser adapter and repairs a broad-IPA scoring bug discovered during CI. It does not claim a new accuracy score, does not infer productive morphology, and does not turn Hangul pronunciation notation into IPA gold.

## Implemented

### 1. Preserve lexical vowel length for the exact dictionary form 수많은

The NIKL Korean Basic Dictionary records **수많은[수ː마는]** ([entry 71144](https://krdict.korean.go.kr/kor/dicSearch/SearchView?ParaWordNo=71144)). The adapter now:
- corrects the exact form to the attested Hangul surface **수마는** if the pinned G2P output differs;
- retains the length mark in the IPA boundary as `suː`;
- leaves the Ukrainian output as the existing IPA-to-Ukrainian adaptation, with no invented Ukrainian length mark;
- scopes the length overlay to the exact input form, rather than generalizing it to a larger phrase.

The source is evidence for the Hangul surface and length notation, not independently reviewed IPA gold. The IPA mapping remains a project adapter decision pending phonetic review.

### 2. Expose the second accepted pronunciation of 멋있어

NIKL Online Q&A [qna_seq=306166](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=306166) explicitly accepts both **[머디써]** and **[머시써]**. When the pinned G2P output is one of these attested surfaces, the adapter offers the other as an alternative.

The alternative's IPA and Ukrainian target are generated by the same surface → IPA → Ukrainian pipeline as the primary output. The variant is marked `lexical-review`; the generated IPA and Ukrainian rendering are not represented as source-provided gold. The browser variant card links to the exact NIKL Q&A source. If the primary G2P surface is outside the two source-attested forms, the adapter fails closed and does not invent a variant.

## Additional benchmark-normalizer fix

CI exposed a bug in `clippyfirst-broad-v1`: globally replacing `ɕ→s` also changed the affricate `tɕʰ` to `ts`. The normalizer now protects `tɕ` before standalone `ɕ` normalization and restores it afterward. A regression test ensures affricate aspiration remains intact. On the pinned 2,655-item comparison, exact-match counts did not change, but the corrected broad-v1 reference denominator is 21,962 characters and CER is 1.6847% native / 1.7303% g2pk (not the previously reported 1.7001% / 1.7461%). This remains sensitivity analysis, not validated accuracy.

## Explicit review-state metadata (2026-10-24)

The browser engine now adds the fields ipaReviewStatus, ipaIsGold, ukrainianTargetReviewStatus, and ukrainianTargetIsGold to both native-engine results and the IPA adapter used by practical G2P mode. These fields deliberately remain negative until independent review is actually recorded. They are separate from the runtime status values (canonical, contextual, lexical, unresolved), which describe processing behavior rather than scientific validation.

The result panel also explains this distinction to users in Ukrainian and explicitly states that generated outputs are not independently expert-validated gold. This is a transparency improvement, not an accuracy increase: independent IPA adjudication and separate Ukrainian-target review remain open acceptance gates.


### Additional exact-form source control: 싫어서

The source register now includes NIKL Online Q&A qna_seq=313981, which directly gives the Hangul surface form 싫어서[시러서] and explains the ㅀ-before-vowel process. A browser integration regression checks the practical G2P surface against that attestation, then verifies that the Ukrainian target is still reproducible from the generated IPA. The test explicitly asserts that neither IPA nor Ukrainian output is promoted to gold. This is a surface-form regression, not an independent phonetic adjudication.


### IPA boundary interoperability fix

The shared browser IPA-to-Ukrainian utility previously split only on whitespace, so a valid dot-separated syllable sequence from the Python research renderer could be treated as one unknown IPA unit. It now treats dots and whitespace as syllable-boundary metadata while preserving the original Korean source spacing in the Ukrainian target. Actual unmapped IPA symbols still fail closed. Regression coverage added; exact-head CI pending.


### IPA-to-Ukrainian feature-loss trace (2026-10-24)

A code audit found that the target adapter mapped aspirated, fortis, and unreleased-stop IPA tokens to ordinary Ukrainian graphemes without an explicit trace record. That was not a source-pronunciation error, but it concealed a real information loss at the IPA → Ukrainian boundary.

The adapter now keeps the original IPA token unchanged and emits a machine-readable features entry when a matched token contains ʰ (aspiration), ͈ (fortisness), or ̚ (unreleased stop). Each record states handling: not-encoded-in-ukrainian-target and explains in Ukrainian that the feature remains in IPA but has no separate target-orthographic marker. This is deliberately a disclosure change, not a new phonology rule or a claim that Ukrainian spelling can represent these contrasts exactly. Existing vowel-length trace behavior is unchanged.

Regression coverage: tests/ipa-target-feature-loss-trace.test.mjs checks aspirated stops, fortis stops/affricates, unreleased stops, and that feature reporting never rewrites the IPA token sequence. The visible trace already renders each feature's IPA symbol and explanatory note.
