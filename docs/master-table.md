# Exhaustive Korean → Ukrainian master table

## Purpose

This release adds the user-facing exhaustive table requested for the system:

| Korean | Ukrainian |
|---|---|
| 가 | ка |
| 각 | как |
| 강 | кан |
| 한 | хан |
| 힣 | хіт |

The complete generated table contains **11,172 rows**, covering the entire modern precomposed Hangul syllable space:

**19 × 21 × 28 = 11,172**

The table is therefore exhaustive for the **Unicode modern Hangul syllable-block inventory**.

## What the table means

The Ukrainian column is a **canonical isolated-syllable graphemic rendering produced by the project model**.

It is not a semantic translation.

It is not a claim that every row is a lexically attested Korean syllable.

It is not a claim that the same Korean block always has the same pronunciation in connected speech.

It is not a replacement for contextual phonological rules.

The distinction is essential because Korean pronunciation is context-sensitive: final neutralization, liaison, assimilation, palatalization, fortition, n-insertion and other processes can change the surface realization. The National Institute of Korean Language documents these processes in the Standard Pronunciation Rules. citeturn5search0turn5search1

## Why there is one Ukrainian value

The requested practical table deliberately has one primary Ukrainian value per Hangul block.

That value is a **canonical baseline**, defined by:

Korean Hangul block → structural decomposition → canonical broad IPA basis → Ukrainian target correspondence → Ukrainian graphemic rendering.

The model does not encode fortis/aspiration as additional Ukrainian letters in the primary two-column projection. Context-dependent alternatives remain in the rule system and analysis layers.

## Exhaustiveness boundary

There are several different meanings of "everything possible":

1. **All modern Unicode Hangul syllable blocks** — finite and exhaustive: 11,172 rows.
2. **All modern Jamo** — a separate finite inventory and included in the scientific model.
3. **All Korean phonological contexts** — not reducible to one finite two-column syllable table because neighboring syllables, phrase boundaries and morphology can change realization.
4. **All lexically attested Korean syllables/words** — requires an external pronunciation dictionary/corpus and cannot be inferred from Unicode combinatorics alone.

The master table covers (1) completely. It does not falsely claim (3) or (4).

## Generation and reproducibility

The table is generated by:

`scripts/generate_master_table.py`

The generator reads the canonical correspondence basis from:

`data/korean/canonical_correspondence.csv`

and the existing Hangul generator.

It writes:

- `data/derived/korean_ukrainian_master.csv` — exactly two columns: `korean,ukrainian`;
- `data/derived/korean_ukrainian_master_audit.csv` — the same rows plus decomposition, IPA, status and provenance metadata.

The GitHub Actions workflow `.github/workflows/master-table.yml` regenerates these artifacts and publishes them as a build artifact.

## Scientific status

The two-column table is intentionally a **presentation projection** of the research model.

The correspondence basis is model-selected and therefore explicitly labelled as such. It must not be read as a normative Ukrainian government transcription standard.

The project's central scientific path remains:

KOR_ORTH → KOR_PHON → KOR_PHON_RULES → KOR_IPA → UA_PHONETIC_TARGET → UA_ORTHOGRAPHY

IPA remains the controlling intermediate representation; the two-column table is derived from it rather than replacing it.

## Sources and model boundary

The Korean side follows the project's documented Korean phonology and the NIKL Standard Pronunciation Rules. NIKL explicitly states that standard pronunciation is based on actual contemporary Seoul standard speech while also considering tradition and rationality. citeturn1search9

The Ukrainian target inventory remains external and version-pinned to Ukrainian-Phonetic-Inventory 0.8.0. The canonical correspondence file records the project-level modelling choices used to produce the simple table.

## Important examples

A block may have a stable isolated baseline but change in a word:

- `넋이` → liaison/complex-coda processing;
- `뚫네` → coda simplification + liquid assimilation;
- `한여름` → potentially n-insertion;
- `먹이` → must not receive n-insertion merely from orthographic adjacency.

Therefore the exhaustive table and contextual rule system are complementary rather than competing representations.
